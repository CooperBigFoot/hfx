# HFX 0.4.0 — GeoParquet bbox covering (HFX spec 0.3.0)

HFX is the open HydroFabric Exchange format: a compiled, source-agnostic
on-disk contract for hydrographic fabrics (catchments, flow topology, and
optional D8 rasters) that any river-network dataset can be normalized into.
This release ships the toolkit that defines and enforces that contract — the
`hfx-core` and `hfx-validator` crates and the `hfx` CLI. `shed` is the
reference engine that consumes HFX datasets.

This toolkit release implements **HFX spec 0.3.0**, a breaking MINOR bump over
spec 0.2.1.

## Headline: first-class GeoParquet

HFX `catchments.parquet` and snap files now carry their bounding box as a
single `bbox` struct with four `float32` leaves (`xmin`, `ymin`, `xmax`,
`ymax`), declared as a [GeoParquet 1.1](https://geoparquet.org/releases/v1.1.0/)
`covering` at `geo.columns.geometry.covering.bbox`. Standard spatial tools
(DuckDB spatial, GeoPandas, geoarrow-rs) recognize the covering and use the
struct-leaf row-group statistics for predicate pushdown — so an HFX dataset is a
first-class GeoParquet file that any spatial tool can query directly, with the
same remote-range-read pruning the engine relies on.

## Breaking changes (spec 0.2.1 → 0.3.0)

- `catchments.parquet` replaces the four flat `bbox_minx`, `bbox_miny`,
  `bbox_maxx`, `bbox_maxy` columns with one non-nullable `bbox` struct; the
  required row-group statistics move to the struct leaves.
- Snap features move to the breaking auxiliary schema `hfx.aux.snap.v2`
  (nullable `bbox` struct, non-nullable leaves); `hfx.aux.snap.v1` is retained
  only for historical datasets.
- `graph.parquet` is unchanged: it has no geometry column, so it keeps its four
  flat bbox columns.
- The validator accepts only `format_version` `"0.3.0"`; `"0.2.1"` and earlier
  are rejected.

## Toolkit changes

- `hfx-validator` reads and validates the covering struct, the covering
  metadata, and the struct-leaf statistics; it dispatches snap on
  `hfx.aux.snap.v2`.
- `hfx-core` adds `FormatVersion::V0_3_0` and `BlessedAuxSchema::SnapV2`.

## Lockstep versioning

`hfx-core` and `hfx-validator` both release as **0.4.0** and move in lockstep:
the validator pins `hfx-core` with an exact `=0.4.0` dependency. See
[docs/VERSIONING.md](https://github.com/CooperBigFoot/hfx/blob/main/docs/VERSIONING.md)
for the two-track (spec / toolkit) policy and the spec-to-toolkit mapping.
